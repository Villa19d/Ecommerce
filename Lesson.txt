## 🛠️ 1. Comandos Frecuentes (Tu Cheatsheet)

### Backend (Django / Python)
*   **Crear Entorno Virtual:** `python -m venv venv`
*   **Activar Entorno:** `venv\Scripts\activate` (Windows)
*   **Instalar dependencias:** `pip install -r requirements.txt`
*   **Crear superusuario:** `python manage.py createsuperuser`
*   **Migraciones (Actualizar BD):**
    *   `python manage.py makemigrations` (Prepara el código)
    *   `python manage.py migrate` (Ejecuta en la Base de Datos)
*   **Correr servidor:** `python manage.py runserver`
*   **Archivos estáticos:** `python manage.py collectstatic`

### Frontend (React / Node)
*   **Instalar dependencias:** `npm install`
*   **Correr servidor de desarrollo:** `npm start`
*   **Construir para producción:** `npm run build`

## 🧩 2. ¿Para qué sirve cada tecnología? (El Stack)

*   **React:** Es tu interfaz. Dibuja los botones, las imágenes y las páginas. Es lo que el usuario ve y toca.
*   **Redux:** Es la "memoria global" de React. React por sí solo olvida cosas entre páginas. Redux guarda el carrito de compras, el usuario logueado y los productos para que cualquier componente pueda verlos sin volver a pedirlos.
*   **Tailwind CSS:** Es tu pincel. En lugar de escribir archivos CSS larguísimos, pones clases directamente en el HTML de React (ej: `bg-blue-500 text-white`) para dar estilo rápido.
*   **Django:** Es el cerebro del servidor (Backend). Recibe las peticiones de React, procesa la lógica (ej: "¿Este usuario tiene permiso?", "¿Hay stock?") y habla con la base de datos.
*   **Django REST Framework (DRF):** Django normalmente devuelve páginas web enteras (HTML). DRF hace que Django devuelva "JSON" (datos puros) para que React los pueda leer y dibujar a su manera.
*   **Djoser:** Es una librería mágica de Django que te crea automáticamente todo el sistema de login, registro, reseteo de contraseña y tokens de seguridad (JWT) sin que tengas que programarlo desde cero.
*   **PostgreSQL / Neon:** Es la bóveda. Aquí se guardan los usuarios, productos y órdenes. Neon es simplemente la versión en la nube de PostgreSQL.

## 🤯 3. LA CLASE MAGISTRAL: Entendiendo React y Redux

Redux siempre parece complicado porque usa palabras raras (Store, Actions, Reducers, Dispatch). Vamos a traducirlo a algo de la vida real: **Un Restaurante**.

### Los Conceptos:
1.  **El Componente (El Cliente):** Es un botón o una página en React. (Ej: La página `Shop.jsx` que necesita ver los productos).
2.  **La Acción (El Mesero - `Actions/products.js`):** El Cliente no entra a la cocina a cocinar. Llama al mesero y le da una orden: *"Tráeme los productos"*. En código, esto se llama hacer un **Dispatch** de una **Action**.
3.  **El Reducer (El Cocinero - `Reducers/products.js`):** El mesero lleva la orden a la cocina. El cocinero lee la orden, procesa la comida (o guarda los datos) y saca el plato listo.
4.  **El Store (La Mesa / La Memoria Global - `store.js`):** Es donde se pone la comida lista. Todos los clientes (componentes) pueden ver lo que hay en la mesa en todo momento.

### El Flujo Paso a Paso en Código (Ejemplo: Cargar Productos)

1.  **En tu Componente (`Shop.jsx`):**
    El usuario entra a la página. El componente dice: *"Necesito los productos"*.
    `dispatch(getProducts())` -> *(Llamaste al mesero)*

2.  **En tu Action (`Redux/Actions/products.js`):**
    La función `getProducts` hace una petición a Django (`axios.get('/api/product/')`).
    Cuando Django responde con los datos, el mesero grita a la cocina:
    `dispatch({ type: 'GET_PRODUCTS_SUCCESS', payload: data })` -> *(¡La orden está lista, aquí están los datos!)*

3.  **En tu Reducer (`Redux/Reducers/products.js`):**
    El reducer escucha el grito `'GET_PRODUCTS_SUCCESS'`. Toma el estado anterior (que estaba vacío) y lo actualiza con los nuevos datos (`payload`).
    ```javascript
    case 'GET_PRODUCTS_SUCCESS':
        return { ...state, products: payload }
    ```

4.  **De vuelta al Componente:**
    Como el Store se actualizó, React dice: *"¡Ah! Cambiaron los datos"*. Y automáticamente re-dibuja la página mostrando los productos usando `useSelector`.

### ¿Por qué molestarse con Redux?
Si no usaras Redux, al cambiar de la página "Tienda" a la página "Carrito" y volver a "Tienda", React tendría que volver a pedir los productos a Django. Con Redux, los productos se quedan en la "Memoria Global", haciendo la app rapidísima.

## 🔄 4. El Flujo de Toda la Aplicación (El Ciclo de Vida de un Click)

Imagina que un usuario hace click en "Iniciar Sesión". Así viaja la información:

1.  **Frontend (React Component):** El usuario llena el formulario en `Login.jsx` y da click.
2.  **Frontend (Redux Action):** El componente llama a la acción `login(email, password)`.
3.  **Red (Internet):** La acción hace un `POST` usando Axios hacia `tu-dominio.com/auth/jwt/create/` enviando un JSON con el email y password.
4.  **Backend (Django urls.py):** Django recibe la petición y revisa sus URLs. Ve que `/auth/` le pertenece a **Djoser**.
5.  **Backend (Django Djoser/Views):** Djoser busca el email en la Base de Datos. Comprueba que la contraseña encriptada (hash) coincida.
6.  **Base de Datos (Neon):** Responde a Django: *"Sí, el usuario existe y la contraseña es correcta"*.
7.  **Backend (Respuesta):** Djoser genera un Token JWT (como una pulsera VIP de un antro) y se lo devuelve a React en formato JSON.
8.  **Frontend (Redux Reducer):** El reducer de Auth guarda ese Token en el `localStorage` del navegador y en el estado global.
9.  **Frontend (Actualización UI):** El Navbar lee el estado global, ve que ya hay un token, y cambia el botón de "Iniciar Sesión" por "Cerrar Sesión" y la foto de perfil.

## 📂 5. Estructura del Proyecto

### 🖥️ Backend (Django)
```text
backend/
├── manage.py        # El ejecutable para comandos de Django
├── backend/         # Carpeta principal de configuración
│   ├── settings.py  # Conexiones a BD, contraseñas, apps instaladas
│   └── urls.py      # El "enrutador" principal (hacia donde van las peticiones)
├── product/         # Aplicación de Productos
│   ├── models.py    # Define cómo se guarda un producto en la BD (Columnas y Tablas)
│   ├── views.py     # La lógica: qué pasa cuando React pide productos
│   └── serializers.py# El traductor: Convierte el modelo de Python a JSON para React
└── user/            # Aplicación de Usuarios (Extiende al usuario normal de Django)
```

### 💻 Frontend (React)
```text
frontend/src/
├── App.js           # Define todas las rutas (URLs) de tu frontend
├── store.js         # La creación de la "Memoria Global" de Redux
├── components/      # Pedacitos de código reutilizables (Navbar, Alertas, Botones)
├── containers/      # Las Páginas completas (Home, Shop, Login)
└── Redux/
    ├── Actions/     # (Los Meseros) Funciones que piden datos al Backend
    └── Reducers/    # (Los Cocineros) Funciones que guardan datos en el Store
```
